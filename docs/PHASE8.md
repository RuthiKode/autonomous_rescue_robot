# Phase 8 (plan week 9): evaluation sweep

Plan gate for week 9: *full sweep, every table generated from the CSV only.*

**Result: done with fewer seeds than planned.** 60 runs finished with status ok, 3-5 seeds per
(condition, world) cell, instead of the planned 10. Every table below is generated by
`scripts/make_tables.py` from `results/sweep/runs.csv` (`docs/results/summary.md`, `paired.md`, `summary.csv`,
`coverage_curves.png`, `pins.png`); nothing is typed in by hand except the reading of the tables.

## Conditions (same worlds, same Gazebo seeds)
| name | explorer | detector | stop rule |
|---|---|---|---|
| random goals | random reachable goals | fine-tuned YOLOv8n | plateau or 900 s |
| explore_lite | explore_lite, upstream default parameters | fine-tuned | plateau or 900 s |
| own selector | own frontier selector + mission tree | fine-tuned | mission DONE/FAILED or 900 s |
| own + verification | as above + Verify branch (pins = verified tracks) | fine-tuned | mission DONE/FAILED or 900 s |
| own + verification, pretrained | as above | COCO-pretrained YOLOv8n | mission DONE/FAILED or 900 s |

Worlds: collapsed, rooms, open_plan.

## Reproduce
```bash
scripts/sweep.sh 1 6                                   # resumable; runs one simulation at a time
python3 scripts/make_tables.py results/sweep docs/results
```

## Why fewer seeds than planned (the sweep itself)
The sweep ran for about 26 h of wall-clock time, and most of that was lost to infrastructure failures, not runs:
1. First attempt: after 5 ok runs, 29 runs in a row ended `map_save_timeout`. Cause: ROS nodes from an earlier
   full-launch test were still running (`cleanup.sh` did not kill `install/rescue_*` processes), so a second
   map/stack interfered. Fixed in `cleanup.sh`.
2. Second attempt: after about 25 ok runs, the simulator segfaulted (gz exit -11) and from then on every run
   ended `map_save_timeout`; about 110 leaked Fast DDS shared-memory segments were in `/dev/shm` and one hung
   `map_saver_cli` was left per failed run. Fix: `scripts/hard_reset.sh` (kill leftovers, clear the segments,
   stop the ROS daemon) now runs before every sweep run.
3. Third attempt: `random goals / rooms / seed 2` hung in teardown twice (49 min the second time) and
   `own selector / collapsed / seed 5` hung for 6 h. The sweep was stopped there.

All failed rows stay in `runs.csv` and are listed at the end of `docs/results/summary.md`; they are not averaged.
With n = 3-5, the tables show trends; only differences whose 95 % interval excludes 0 are claimed below.

## What the data supports
1. **Fine-tuning the detector matters most.** Recall with the fine-tuned YOLOv8n is 0.61 higher (paired, 95 % CI
   +0.39 to +0.83) than with COCO-pretrained weights; the pretrained model found survivors in 1 of 13 runs.
2. **Verification, as built, costs recall and did not buy precision.** Counting only verified pins lowered recall
   by 0.22 (CI -0.41 to -0.03); the precision change is not separated from zero (-0.08, CI -0.28 to +0.12). In
   rooms and open_plan some true survivors were not verified before the mission ended (2 visits per pin, 15
   close views needed).
3. **Own selector vs explore_lite: not separated.** Own is faster to 90 % on average (-35 s) but the interval is
   wide ([-113, +42] s); explore_lite has higher mean coverage in rooms. Own selector vs random goals is not
   separated either at this n.
4. **The own mission ends by itself**: DONE in 0.75-1.00 of runs (mission times 213-546 s); explore_lite has no
   completion signal and random goals never complete.
5. **rooms is the weak world** for every frontier explorer: ATE RMSE 0.4-1.5 m (vs 0.03-0.09 m elsewhere), 3.5-5.2
   recoveries per run for the own mission, map IoU down to 0.48. SLAM pose jumps in the narrow doors are the
   suspected cause (see PHASE6 known issues); not fixed.

## Deviations and known issues
- 3-5 seeds per cell instead of 10 (see above); the plan's "10+ seeds" was not met.
- explore_lite mission columns (DONE share, recoveries) are n/a: it has no mission tree.
- Seeds differ between cells (the ok runs are not the same seeds everywhere); paired comparisons use only
  world+seed pairs present in both conditions.
- ATE/IoU in rooms have large spread; one bad SLAM run moves the mean a lot.
